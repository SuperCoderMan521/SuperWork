## desktop（packages/desktop，Electron）AskUserQuestion 无交互渲染的根因分析

桌面端权限链路：QueryEngine(headless) → createDesktopCanUseTool（desktop-query-runner.ts）→ 核心管线返回 ask → PermissionBroker 发 permission.requested → renderer PermissionPanel（通用三按钮）→ permission.resolve 仅回传 decision → toCorePermissionDecision 回传**原始 input**。

四个断点：
1. 协议层：`permission.resolve` schema 只有 permissionId+decision，无 payload 字段，answers 无法回传
2. Core 层：createDesktopCanUseTool 对所有 ask 一刀切走通用 broker，无 AskUserQuestion 特判；allow 后 updatedInput=原始 input（无 answers）→ call() 得空 answers → 模型收到 "User has answered your questions: ."
3. Renderer 层：PermissionPanel 只渲染 summary 字符串+deny/allow_once/allow_session，完全忽略 request.input（questions 其实已送达）
4. 架构层：TUI 问答对话框是 Ink 组件，desktop 是 DOM renderer + headless QueryEngine，无 REPL screen，TUI 组件不会挂载

修复方案：协议加通用 payload 通道 → broker/dispatcher/preload 透传 → createDesktopCanUseTool 对交互工具注入 answers 到 updatedInput → renderer 新增 AskUserQuestionPanel 按 toolName 分发。注意 ExitPlanModeV2 同属 requiresUserInteraction 工具，payload 机制应通用化。

## 方案 A 边界确认（用户追问：是否改 query loop 核心）

结论：不改。零 src/ 改动。依赖两个既有核心扩展点：
1. QueryEngine 构造函数注入 canUseTool（QueryEngine.ts:144）——desktop 已用 createDesktopCanUseTool 替换 TUI 的 useCanUseTool（desktop-query-runner.ts:266/278），AskUserQuestion 特判只加在这个工厂内
2. 标准 PermissionDecision.updatedInput 契约——核心工具执行一律用 updatedInput ?? input（toolHooks.ts:356、PermissionContext.ts:209），answers 注入 updatedInput 与 TUI 路径完全一致；answers 本就在 AskUserQuestionTool inputSchema（commonFields）内，过校验零改动
另：permissions.ts:548/1253 requiresUserInteraction 工具短路 ask（bypass 模式也不例外），desktop broker 天然接住。改动全部限于 packages/desktop/**（shared/core/electron/renderer/tests）。
